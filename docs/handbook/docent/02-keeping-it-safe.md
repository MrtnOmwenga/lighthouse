# Keeping the assistant safe to run

A public page that calls a paid language model, speaks for a person, and stores what visitors
type. This page is about what could go wrong with that and what was built against each.

## The words used on this page

- **Prompt injection:** text that tries to give a model new instructions, typed by a visitor or
  hidden in something the model reads.
- **Edge:** the Cloudflare Worker in front of the site. Every request passes through it.
- **Firewall (WAF):** a filter in front of a service that blocks requests by rule.
- **Least privilege:** giving each part permission for its own job and nothing else.
- **Rotation:** replacing a secret on a schedule, so a stolen copy stops working.

## What is there to protect?

Five things, in the threat model's order: the money the model costs, what is said about the
author, visitors' conversations, the secrets, and the site the assistant runs inside. The threat
model (`docs/threat-model.md`) was written before the infrastructure and lists 21 threats, each
tied to the code that answers it.

## What can a prompt injection achieve?

A sentence. The design aims for that to be all.

- **It has nothing to act with.** Its only tools read its own index. It can't browse, run code,
  send anything, or change anything.
- **Its instructions hold nothing secret,** so "print your prompt" reveals nothing.
- **A reply must rest on sections it was shown,** checked in code, so it can't be talked into a
  claim about the author with no source.
- **It never produces an address.** Further reading is a section's id checked against the index.
- **A reply is plain text, shown as text.** Markup in a reply is not executed.

All 14 injection attempts in the evaluation set fail. What remains accepted: it can be talked
into a rude or silly sentence in that visitor's own session.

## What stops someone running up the bill?

Checked in this order, before any model call:

1. the request came through the edge (a shared secret; without it the service answers "not
   found");
2. it is the right shape and under 8,000 bytes;
3. the caps allow it: 25 questions a visitor a day, 20 turns a conversation, USD 0.40 a day and
   5 a month. A reply is at most six model calls and 900 tokens.

A visitor is counted by a fingerprint of their address that changes every day. A refused request
changes nothing and costs nothing.

## What if the caps themselves fail?

Then something outside them has to notice. The service writes counts to its log in a form
CloudWatch reads as metrics, with no words of any visitor in them. Alarms watch those counts.
Three signals switch the service off by themselves: a day's spend above the cap, 3,000 calls in an
hour, or the month's budget reached. Off means AWS refuses every call before any code runs, and
the window on the site says the assistant is resting.

It is switched back on by a person, with one command, after they have looked. The switch was
rehearsed on the live service on 10 October 2026: four seconds from the signal to off. The
rehearsal found that the edge passed AWS's refusal to the browser as it came; the edge now turns
it into the same plain reply as any other outage.

## What does the firewall add?

With the full controls on, the only way in is API Gateway behind a firewall, and the function's
own address doesn't exist. The firewall blocks a request with no edge secret, a body over 8,000
bytes, more than 60 calls in five minutes from one visitor's address (read from a header the edge
sets, since every call arrives from Cloudflare), and Amazon's list of known attacks on software.

**It does not stop prompt injection, and this was measured:** all 14 injection attempts pass it.
They are ordinary text. The firewall bounds volume and shape; the service bounds meaning.

## How are the secrets kept?

Three secrets. None is in an environment variable, the repository or the logs.

| Secret | Where | How it is replaced |
|---|---|---|
| The model's key | An encrypted parameter, put there from a keyring by a script | By hand: revoke, make a new one, store it |
| The edge's secret | An encrypted parameter, generated by Terraform | By hand: it is shared with the site's edge, so both sides change |
| The fingerprint key | Secrets Manager | By itself, every 30 days. Nobody else holds a copy, so nothing needs co-ordinating |

Each function has its own role: the service may use its table, its secrets and its log; the off
switch may set one function's concurrency; the rotation may change one secret. A test reads the
Terraform and fails if any role holds a wildcard.

## What did the AWS account's plan rule out?

The account is on AWS's free plan, which cannot be charged. It refuses GuardDuty and Security
Hub, so there is no AWS-side threat detection and no benchmark score. It refuses GitHub's
federated sign-in, so deploys run from a signed-in machine with credentials that expire in hours,
not from CI. And Claude through Bedrock is refused, so the model is called through Anthropic's own
API. Each is written down as accepted, with what stands in for it.

## Known gaps

- **The alarms' thresholds are guesses** until there is traffic to compare them with, and none
  has fired for real.
- **The build is not signed.** The function records the commit it was built from.
- **One shared secret between the edge and the service.** Whoever holds it can call the service
  directly, still under every cap.
- **The full controls cost about USD 10 a month** from the account's credits, and are planned to
  be switched off after a month. Without them there is no rate limit before the function runs.

## Questions and answers

**How do you defend against prompt injection?**
By limiting what a successful injection can do. The model can only read its own index, holds no
secrets, can't produce a link, and can't send a claim that has no source. Then a test set of
attempts is run to check.

**Does a web application firewall help with that?**
No, and the measurement says so: it blocked none of the attempts. It is there for volume, size and
known attacks on software.

**What stops this costing a fortune overnight?**
Caps checked before every model call, a ceiling of five copies running, and an off switch tripped
by spend, by a flood, or by the budget.

**Why does the fingerprint key rotate and the others not?**
It is the only one nobody else holds. The other two are shared with another system, so a machine
replacing them alone would break the service.

**What would you add with a paid AWS account?**
Threat detection (GuardDuty), a benchmark of the account's settings (Security Hub), and deploys
from CI with no stored keys.
